# UI direction after first prototype feedback

User feedback: too much text, hidden inputs, confusing navigation, insufficient Pittsburgh identity. The first bridge-and-cards revision was explicitly rejected. User requested frontend design guidance, Rescope as visual reference and a Steelers reference.

Reviewed Rescope's public website and parcel product screenshot, September 26, 2026. Reference: https://www.rescope.co/. No assets or product claims copied. Read published frontend-design guidance: https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md.

## Design

Property workspace, not a marketing page. Keep the parcel on the left and an editable proposal panel on the right. Proposal, comparison and evidence tabs change the working panel. Export is always available. No introductory slogan or decorative bridge. On mobile the diagram collapses to a compact property header so inputs remain close to the top.

Colors: black #000000, Steelers gold #FFB612, white #FFFFFF, light gray #F1F2F2, steel gray #68717A. Red and blue appear only as small steelmark-style identity accents, not as invented feasibility signals.

Type: locally bundled IBM Plex Sans for controls and headings, IBM Plex Mono for parcel identifiers and coordinates. Left alignment throughout. Strong functional hierarchy without uppercase eyebrow labels above every section.

The real projected parcel outline is the visual anchor, with accurate aspect ratio, north arrow and scale in US survey feet. No fabricated building, street network, slope coverage, satellite image or compliance dimensions. A steelmark-inspired Pittsburgh 412 badge and gold header stripe supply the requested Steelers reference without implying affiliation.

Critical conflict stays visible. Full source reasoning is expandable. Inputs remain hypotheses. The functional data and rule boundaries are unchanged.
