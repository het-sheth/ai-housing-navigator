# Housing Navigator

Keep application code here and research in `../ai-housing-hackathon-wiki`. Read `docs/current.md` and the wiki's accepted `docs/product-spec-v1-2026-09-26.md`, `docs/product-decisions-2026-09-26.md` and ADR 0006 before changing behavior. The accepted product leads with proposal assessment and prioritized next actions; comparison is secondary. Countywide Allegheny County intake accepts all housing work activities and combinations with bounded, disclosed check coverage. Use named check statuses and an evidence/action checklist without an overall score. V1 includes useful 2D site context.

The existing feature branch publishes a bounded Lanark comparison prototype through open PR #1. Its current interface is historical implementation, not the accepted expanded workflow. The selected foundation is npm, React, TypeScript, Vite, Supabase Postgres and Supabase Auth, with Vercel planned. The wiki's ADR 0007 and technical design contain proposed engineering details, not blanket implementation approval. No expanded application implementation or deployment is authorized by publication of the prototype.

No credentials or personal records. No em dashes. Preserve parcel identifiers as strings, unknowns and source conflicts. Never issue permission verdicts or numerical feasibility scores. Run `npm test`, `npm run typecheck`, `npm run lint` and `npm run build` after changes. Feature branches only; never push main directly.
